When it upscales

Target size, ratios, source limit

These five values only mean something together; the example below works them out from what is in the boxes.

Height to upscale to when a session does not ask for a size of its own. Width follows the source aspect ratio. Ignored while "Only upscale when the viewer asks for it" is on. Default 1080.
Ceiling on any upscale, including sizes the player asks for. Default 2160.
No upscale unless the target is more than this multiple of the source height; a 1080p source to 1080p is 1.0 and is skipped. Also decides which items the direct-play option below applies to. Default 1.15.
Run the super-resolution network only at or above this ratio; below it the upscale still happens, with plain scaling plus unblur and refinement. The fixed-2x networks measured no better than plain scaling under about 1.5x while costing about 15% of throughput, so the default keeps 720p to 1080p on plain scaling. RAVU-Zoom scales to any ratio and is never skipped. 0 disables the check. Default 1.60.
Sources taller than this are not upscaled (other enhancements still apply). Portrait video is judged on its long edge instead. Default 1440.

Default levels

What runs when a player does not choose, and what players may use

Each level applies when a session does not pick its own. The Allow box is a master switch for that enhancement.

Upscale and sharpen

Super-resolution, scaling kernel, unblur
Used when the player does not pick its own. FSRCNNX (default) measured best on real footage at both 1.5x and 2x. Anime4K is a generic 2x network that only matches FSRCNNX at exactly 2x (540p to 1080p); try it by eye. The percentage after an option is its GPU cost relative to plain scaling, from one 480p to 1080p run; the same applies to the refinement and chroma options below. A level whose shader file is missing from the shader directory (see File locations) falls back to plain scaling without an error; the Recent sessions table shows what ran.
Scaling kernel under the shaders. Players can pick another per session. The list comes from the server, because a kernel name libplacebo does not know fails the whole transcode. Default ewa_lanczos.
Master switch. Off: no session can turn it on, and the default below is ignored.
Sharpening applied after scaling. Gentle to Strong is AMD RCAS, nearly free. NVSharpen gives slightly more visible detail at about 10x the GPU cost of RCAS; a matter of taste. Dropped automatically when the NVScaler shader is selected, which sharpens on its own. Default Off.

Clean-up

Denoise, deblock, deband
Master switch. Off: no session can turn it on, and the default below is ignored.
Runs before the upscale so noise is not reconstructed as detail. Light is a cheap temporal CPU filter; Strong and Max are nlmeans on the GPU. OIDN and both OptiX levels run through the patched ffmpeg and are the best measured on genuinely grainy sources, and a no-op on clean ones; none is in the player's quality ladder. Denoise costs about 60% of throughput, so it is worth turning on only for noisy sources, especially if unblur is also on: sharpening a noisy source without it measured a net loss. If a session combines a GPU denoise with a patched-only filter on an older ffmpeg build, the denoise is dropped and the session record says so. Default Off.
Master switch. Off: no session can turn it on, and the default below is ignored.
Removes the source encode's block edges and ringing before anything scales them up; the networks otherwise treat them as detail. Light and Strong address blocking only; fspp and pp7 also remove ringing at more CPU cost. All are single-threaded CPU passes at source resolution. Not run together with the RTX DLPP/VSR neural levels. Default Off; no strength has been measured on this content.
libplacebo debanding on the scaling pass. Removes the banding low-bitrate video shows in dark gradients; measured as free. Players can turn it off per session. Default On.
How aggressively banding is smoothed. Higher removes more banding and more real gradient with it. 0 to 1000, default 3.
Synthetic grain added back after debanding. 0 by default on purpose: libplacebo's own default (6) adds texture this content does not need. 0 to 1000.

Detail and colour

Refine, chroma
Master switch. Off: no session can turn it on, and the default below is ignored.
Corrects the scaled image so that shrinking it back reproduces the source. Runs on top of any super-resolution shader or plain scaling, and at every ratio, including between the minimum scale factor and the super-resolution minimum ratio, where nothing but unblur runs. Costs one GPU pass; unmeasured for quality. Default Off.
Master switch. Off: no session can turn it on, and the default below is ignored.
Rebuilds the colour planes (stored at quarter resolution in 4:2:0 video) using the luma plane as a guide. Works with any super-resolution level and also without an upscale. GPU moderate; unmeasured for quality. Default Off.

Neural and game upscalers

AI models, DLSS / FSR-style game upscalers
Master switch. Off: no session can turn it on, and the default below is ignored.
Real-ESRGAN networks run through the patched ffmpeg before the scaling pass; they combine with the super-resolution shader rather than replacing it. All three are far below realtime on this GPU (24, 15 and 10 fps at 540p to 1080p, against 265 fps without) and the player's quality ladder never selects them. The weights are not shipped: a level whose .onnx file is missing from the Neural model directory (see File locations) is not offered to players. The RTX DLPP and RTX VSR levels can be chosen in the player but not set as a default here. Default Off.
Master switch. Off: no session can turn a game upscaler on, and the default and the three sources below are ignored.
FSR2 and DLSS are built for game engines that supply motion vectors, depth and camera jitter. A video has none of those, so every input is estimated and the result is a temporal denoise plus a fixed upsample: expect ghosting, not super-resolution. Offered because they were asked for, labelled degraded everywhere, never chosen automatically. fsr2 and dlss replace the super-resolution shader and refinement; dlaa runs 1:1 before the normal scale. dlss and dlaa need the NVIDIA DLSS runtime installed by hand (see File locations) and are otherwise not run. Not available together with the RTX DLPP/VSR neural levels. Default Off.
Only used when a game upscaler is active. None of the four is correct for recorded video; "measured" is the least wrong. Default measured.
Only used when a game upscaler is active. "Monocular estimate" needs the depth model file (see File locations) and falls back to a flat plane without it; the session record says so. "Flat" is a known no-op; the estimate can add ghosting. Default Monocular estimate.
Only used when a game upscaler is active. Flow inconsistency marks occluded areas so history is not reused there. It is the main anti-ghosting control, at the cost of one extra optical-flow pass. Default flow.

Transcode policy

Which sessions are enhanced, and how they are encoded
On: the target height above is ignored and a session is upscaled only when the player's Enhance menu asked for a size. This gates the upscale only: the other defaults on this page (unblur, denoise, deblock and so on) still apply to every transcode, so set those to Off too if you want untouched sessions. "Enhance direct play too" below ignores this setting. Default Off.
When Jellyfin would copy the video stream unchanged (remux), transcode it instead so the enhancement chain can run. Applies to any enhancement set on this page, not only upscaling, and to every client. Costs a GPU transcode per session. Default Off.
Off by default; expensive. When a client could play a file directly there is no ffmpeg process and nothing to enhance. On: direct play and direct stream are refused for every item the upscale settings above would act on (size, minimum scale factor, maximum source height), on every client, so each becomes a GPU transcode subject to the concurrency cap, and past the cap a plain transcode that costs more than the direct play it replaced. Only needed for clients that do not run the web player script; the web player already forces a transcode when a viewer picks something in the Enhance menu. It ignores "Only upscale when the viewer asks for it", so with that on, clients are refused direct play and then get no enhancement.
Hands NVENC the finished frame directly instead of copying it to system memory and back, which saves one full frame of PCIe traffic each way at output size. On by default. If sessions fail to start on your build, turn it off; nothing else in the chain changes.
Video encoder for transcodes this plugin enhances, including ones it forces out of a stream copy. Blank or auto follows the codec the client negotiated. A named encoder (hevc_nvenc, h264_nvenc, ...) is used only if this ffmpeg has it and the client said it can play that codec; otherwise the negotiated codec is kept and Recent sessions shows why. Default hevc_nvenc.

Capacity

How many enhanced transcodes may run at once
Past this many enhanced ffmpeg processes, new sessions play through the stock path and the session record says "all enhancement slots busy". 0 turns enhancement off for everyone. Counts processes running the GPU shader chain; a session using only the RTX DLPP/VSR levels is not counted. Default 4.
A setting change during playback briefly runs a second ffmpeg so the old stream keeps serving until the new one is ready. That second process also counts against the cap above. Past this many swaps at once (or 0), a live change falls back to stop-and-restart. Default 4.

File locations

Shaders, models and runtimes; defaults suit a standard install

Where this plugin looks for the files it needs. The defaults suit a standard install, so leave them alone unless you have put something somewhere else.

Where the .glsl shader files live. Default /usr/share/jellyfin-shaders. A level whose file is missing disappears from the player menu and, if set as a default above, silently falls back to plain scaling.
Where composed shaders and libplacebo's compiled-shader cache are written. Must be writable by the Jellyfin service user; if it is not, shader passes silently do not run. Default /var/cache/jellyfin/jellyfin-plus-shaders.
Where the Real-ESRGAN ONNX weights live. Not shipped with this plugin; a neural level whose file is missing is not offered. See NEURAL.md for how to export them from the official checkpoints.
Directory containing libnvidia-ngx-dlss.so.* (NVIDIA proprietary, not shipped). Until it is there, dlss and dlaa are not run. Default /usr/lib/jellyfin-ffmpeg-oidn/dlss. See DLSS.md.
The monocular depth ONNX model the game upscalers are fed instead of a real depth buffer. Not shipped; without it those levels fall back to a flat plane. Default /usr/lib/jellyfin-ffmpeg-oidn/models/depth_anything_v2_vits.onnx.
Where nvdlppx.dll lives, for the dlpp-1 to dlpp-4 neural levels. Proprietary and not shipped, so until you put it here by hand these levels are not offered to players. They are player-only: this page cannot set them as a default. Default /usr/lib/jellyfin-ffmpeg-oidn/rtxdlpp/dll/nvdlppx.dll. See RTXDLPP.md.
Where nvaivpx.dll lives, for the vsr-rtcuda neural level, a fast GPU resample rather than a network. Same rules as above: not shipped, not offered until installed, player-only. Default /usr/lib/jellyfin-ffmpeg-oidn/rtxvsr/dll/nvaivpx.dll. See RTXVSR.md.

Timeline markers

External services that put markers on the seek bar
A JSON array of providers. For each played item whose path matches a provider, the server asks that provider's URL for markers and the player draws them on the seek bar; a click seeks just before one. The server makes every call, so players never need to reach these addresses. Empty ([]) turns markers off. The environment variable JELLYFIN_PLUS_MARKER_PROVIDERS, when set, replaces this list. Contract and mapping keys: docs/architecture/TIMELINE_MARKERS.md. Invalid JSON is not saved: the previous list stays.
Hovering a marker shows frames from that moment. Videos with Jellyfin trickplay use it; for the others the server makes a few small frames at each marker (and 5 and 10 seconds either side) the first time someone hovers one, with the ffmpeg Jellyfin is configured with, at low priority. They are kept in Jellyfin's cache folder (at most 512 MB, oldest dropped first), never beside the video. Off: those videos show the marker's label only.
